Sources to Surfaces

Read top to bottom. Data enters through two ingestion paths on the left (scheduled connectors, LLM distillers) and one live path on the right (queried at run time, never stored). Everything ingested lands in the shared layer; every rep ask flows through planner → primitives → evidence → cited answer; finished threads loop back in as team knowledge.

02 Ingestion runs on its own clock — keeps the store stocked before anyone asks
Deterministic · scheduled
Connector jobs
One module + manifest per source in connectors/. Each run: fetch since watermark → qualify → map to contract → validate → write. Idempotent (dedupe keys). Per-source cadence: sfdc_history nightly · gong_ingest hourly · usage_shift daily · harvestapi weekly. New source = one small reviewed contribution.
LLM extractors
Distillers
One schema per content type: new-business calls {pain, objection, competitor, trigger…} · AM/CS calls {adoption blocker, expansion cue, renewal risk} · threads {question, answer, human additions, reactions}. Embed the artifact, never the raw transcript. Reactions gate what's kept. Output is schema-validated before write.

04 Query side per run — retrieval is instant because collection already happened
Trigger
Rep asks in Slack
@Junto / thread reply / slash syntax. Gateway acks <3s, passes speaker identity into the run.
Decision
Planner
Reads the capability catalog (from the skills registry). Selects tools explicitly, fans out in parallel — or DISCOVER / HELP. If the catalog has no source for the ask → Request-this-source button.
Deterministic reads
Read primitives
LLM-free queries over the index + live adapters. Every read filtered by the requester's visibility BEFORE any LLM sees it. Same primitives exposed over MCP later.
LLM synthesis
Evidence → answer
All fetches normalize to evidence rows {source, snippet, date, subject, confidence}. Every claim traces to a row; citations + denominators (scanned N → matched M) fall out free; failed fetches declared.

The compounding loop. A finished Slack thread (Junto's answer + the humans' additions + reactions) goes quiet → the distiller turns it into a knowledge artifact with the thread's permalink → it lands in the shared layer → the next rep's ask retrieves it, cited with the teammate's name and a link to the real thread. Today's runs are tomorrow's context.
Rep vs owner: reps see visibility-scoped Tables, Knowledge base, Logs (+ their private My activity), and provenance everywhere. The owner additionally sees Sources health (cadence, watermarks, failures), Review labeling, Pending actions (source requests + future write approvals), the audit trail, and the Sim back office.
